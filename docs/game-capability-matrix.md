# Tested game capability matrix

Published from passed checks on November 14, 2026 at 9:11 AM (America/Chicago).

This matrix separates implemented controls from executed fixture/browser checks and live game certification. **No live game builds are certified by this publication.** A synthetic Steam `latest` fixture is not an installed build ID. A version label on a disposable record is not proof that the corresponding game ran.

The panel provides this matrix under **Compatibility** and **Configuration → Operations → Game compatibility**. Each instance has a **Capabilities** tab showing its exact version/loader, host restrictions, setup requirements, permission blockers and running/stopped requirements. Unknown versions remain unverified; unsupported tabs explain the reason before mounting their controls.

## Recorded checks

Machine-readable passed runs, exact labels, architecture, Node version, source SHA-256 and scope are shipped in [`game-capability-evidence.json`](../server/src/compatibility/game-capability-evidence.json). The latest local/CI report is written to `artifacts/game-capabilities/report.json`.

- **contract / win32 / x64** — server/test/game-capabilities.mjs: Capability metadata, simulated OS restrictions, permission/state blockers, exact-version evidence isolation and API authorization. No game installation or boot.
- **browser / win32 / x64** — server/test/game-capabilities.mjs: Chromium matrix filters, unavailable-tab guards, supported controls and mobile overflow checks. No game boot.
- **fixture / win32 / x64** — server/test/game-controls.mjs: Native configuration round trips and launch arguments for every listed profile; representative map/world import and Satisfactory API fixtures. No live server or installed Steam build.
- **browser / win32 / x64** — server/test/game-controls.mjs: Chromium navigation and supported game controls; unavailable host tabs are checked as blocked. No live game validation.
- **fixture / win32 / x64** — server/test/game-customization.mjs: TF2 configuration/uploads and Minecraft gamerule generation, edition naming, proxy exclusions and permissions. Bedrock command dispatch uses a fake process; no game boot.
- **browser / win32 / x64** — server/test/game-customization.mjs: Chromium navigation and supported game controls; unavailable host tabs are checked as blocked. No live game validation.
- **fixture / win32 / x64** — server/test/world-health.mjs: Synthetic region/NBT and Terraria file-envelope scans, safe-repair safeguards and fixtures. Minecraft version is the fixture record label, not a certified live data-version/build.
- **browser / win32 / x64** — server/test/world-health.mjs: Chromium navigation and supported game controls; unavailable host tabs are checked as blocked. No live game validation.
- **fixture / win32 / x64** — server/test/operations.mjs: CS2 match validation, players, demos and permissions through simulated RCON, with fixture downloads. No installed game build.
- **fixture / win32 / x64** — server/test/game-reliability-workflows.mjs: Minecraft protocol, spark-command observations, backups, staging, moderation and TF2 tournament/FastDL workflow fixtures. No game installation or runtime certification.

## Refreshing evidence

Run `npm run test:capabilities` for the build plus backend/browser suites. Set `OUTPOST_TEST_BROWSER` to a Chromium executable when auto-discovery is insufficient. Tests use disposable data, fixture processes and simulated provider responses. They do not download, install or start production games.

After reviewing a successful run, use `npm run capabilities:publish` to rerun all required checks and refresh this document and the shipped evidence. Publishing requires browser checks, writes only after every suite passes, and preserves prior OS runs with their own dates/source fingerprints. Rebuild afterward so the new JSON is copied into the server distribution. CI produces reports and screenshots without modifying the checked-in evidence.

Live certification is separate work: record the exact game/loader/build ID, host OS/architecture, dependency versions, tested actions and results from a disposable real installation before adding a reviewed live evidence record. Current fixture/browser rows must never be promoted to live status.
